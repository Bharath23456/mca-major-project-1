# Testing and evaluation

## Test environment

Record the actual Python version, OS, Docker Engine/Compose versions, and
dependency versions with the final project submission. Unit tests use the
repository's synthetic labelled samples and FastAPI's in-process test client.
Configuration and container checks are performed separately.

## Automated coverage

Install the development dependencies once, then run:

```powershell
python -m pip install -r requirements-dev.txt
ruff check app tests
pip-audit -r requirements-dev.txt
python -m pytest -q
docker compose config --quiet
```

On Ubuntu/Linux, use the same commands from the repository root.

The anomaly evaluation constructs an independent deterministic test split
containing generated normal and deliberately unusual rows. Precision, recall,
F1, and the confusion matrix are calculated at runtime by scikit-learn. They
describe only this synthetic distribution; they are not performance
measurements on a real cloud host.

## Evaluation limitations

- Synthetic labels are generated by construction, so scores are not an
  unbiased estimate of live performance.
- There are no supplied real-world labeled incidents or reference papers yet.
- Resource usage and metric-collection coverage must be measured on the actual
  demonstration host; do not infer them from the Compose file.
